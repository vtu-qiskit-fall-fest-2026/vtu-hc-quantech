## 2. Pluggable Model Architecture

The inference stack is governed by `backend/ai/providers/` and orchestrated via `AITutorService` in `backend/ai/tutor.py`:

```
                       [ Student Input Query ]
                                  │
                                  ▼
                     [ Scoped BM25 Retrieval ]
                      (Curriculum Topic Packs)
                                  │
                     ┌────────────┴────────────┐
                     ▼                         ▼
            [ LLM Available? ]        [ LLM Unavailable ]
             (Ollama/Gemini/API)               │
                     │                         ▼
            [ Generates Answer ]      [ DeterministicFallbackTutor ]
                     │                (Pedagogical Pack Assembly)
                     └────────────┬────────────┘
                                  │
                                  ▼
                    [ Deterministic Physics Engine ]
                     (backend/quantum/validation.py)
                     (backend/ai/response_validator.py)
                     - Normalization (sum |c_i|^2 = 1.0)
                     - Born Rule (P(i) = |c_i|^2)
                     - Unitary Invariance (U† U = I)
                     - Misconception Detection
                                  │
                                  ▼
                   [ Verified Student Output ]
                   - Honest Source Labeling: "llm" | "fallback"
                   - Confidence Score & Physical Alerts
```

### Pluggable Providers (`backend/ai/providers/`):
1. **Ollama Provider (`backend/ai/providers/ollama.py`)**:
   - Default target: `http://127.0.0.1:11434` running `llama3:8b` or `llama3.2`.
   - Latency: ~500ms–2000ms depending on GPU/CPU acceleration.
   - Temperature: `0.3` (restrained for factual physics fidelity).
2. **Deterministic Fallback Tutor (`backend/ai/fallback.py`)**:
   - Zero-dependency local engine operating with sub-25ms latency.
   - Synthesizes exact physical definitions, Born rule arithmetic, circuit telemetry, and misconception refutations directly from loaded curriculum packs.
   - Automatically engaged whenever external LLMs are offline, unconfigured, or when generated responses fail mathematical validation.

## 3. Honest Source Attribution & Labeling

To eliminate false confidence in AI-generated responses:
- Every API response explicitly returns `"generated_by": "llm"` or `"generated_by": "fallback"`.
- If generated by an LLM, the exact model name (e.g. `"llama3"`) is returned.
- If generated by the deterministic tutor, `"model": null` is returned to prevent users or auditors from believing a model hallucination came from a neural network or vice versa.
- The `ResponseValidator` attaches confidence scores ($0.0$ to $1.0$) and ground-truth verification notes whenever discrepancies occur.

## 4. Supervised Fine-Tuning Specification & Roadmap

When computational resources (e.g. NVIDIA A10G / T4 GPU) are allocated for fine-tuning, the prepared pipeline in `notebooks/quantum_model_training.ipynb` follows this specification:

- **Base Foundation Model:** `meta-llama/Meta-Llama-3-8B-Instruct` or `Qwen/Qwen2.5-7B-Instruct`
- **Tuning Technique:** Parameter-Efficient Fine-Tuning (PEFT) via QLoRA (4-bit NF4 quantization)
- **LoRA Configuration:**
  - Rank ($r$): 16
  - Alpha ($\alpha$): 32
  - Target Modules: `q_proj`, `k_proj`, `v_proj`, `o_proj`, `gate_proj`, `up_proj`, `down_proj`
  - LoRA Dropout: 0.05
- **Optimization Parameters:**
  - Optimizer: `paged_adamw_8bit`
  - Learning Rate: $2 \times 10^{-4}$ with cosine annealing
  - Batch Size: 2 per device with 4 gradient accumulation steps (effective batch size: 8)
  - Epochs: 4–6
- **Validation:** Loss monitoring on `topic_1_1/eval.jsonl` with early stopping if evaluation perplexity stops improving.
